# 표 열 너비 개선 설계

## 목표
표(Table) 블록의 **열 너비(colWidths) 관리**를 안정화하고, **패널과 표 본체 양쪽**에서 직관적으로 조정할 수 있도록 개선. 기존 기능의 **구조는 유지**하고 내부 계산 정확성과 UI 옵션만 확장 (Claude.md 규칙: 최적화 시 기능 구조 불변).

## 문제 인식 (2026-04-19 리뷰 결과 요약)
1. **누적 오차**: 드래그 리사이즈 후 `normalizeColWidths`가 전체를 비례 축소 → 조작 안 한 열까지 값이 변해서 반복하면 점점 틀어짐.
2. **자동저장 재덮어쓰기**: `blocks.js:217`이 1.5초마다 DOM `offsetWidth`를 `%`로 환산해 `colWidths`를 덮어씀 → 반올림 진동 발생.
3. **단위 혼합**: 드래그 중 `px`, 저장은 `%`. 창 크기 변경 시 복원 결과가 드래그 결과와 어긋남.
4. **발견성**: 열 너비 조정 수단이 "헤더 우측 테두리 드래그" 뿐 → 마우스 없는 환경·정확한 비율 지정 불가.
5. **경계값 처리**: 삽입 시 평균 계산이 `splice` 이후 길이 기반으로 틀어짐, max-width 없음.

## 데이터 모델 변경
```javascript
// 기존 (유지)
{id, type:'table', rows, colWidths:[40,30,30], ...}

// 변경 없음 — 내부 저장 단위는 여전히 % (하위 호환)
// 단, 저장 정밀도를 정수 → 소수점 2자리까지 허용
// 예: [33.33, 33.33, 33.34]
```
**호환성**: 기존 `colWidths: [33,33,34]` 형태도 그대로 유효. 새 코드가 소수 허용만 추가.

## 설계

### A. 드래그 리사이즈 개선 (표에서 조정)

**현재 동작:**
- 헤더 오른쪽 테두리 8px 영역 드래그 → 해당 열만 `px` 변경
- 드래그 종료 시 `th / table * 100` 으로 `%` 환산 → `normalizeColWidths`가 전체를 재비례

**개선 동작:**
- 드래그 중에도 `%` 단위로 계산 (컨테이너 너비 대비)
- **이웃 열 보상 방식**: 드래그한 열이 Δ% 증가하면 **오른쪽 이웃 열**에서 Δ% 감소
- 오른쪽 이웃이 최소치(5%)에 도달하면 그 다음 오른쪽 열에서 차감
- 마지막 열 리사이저 드래그 시는 왼쪽 이웃 보상 (역방향)
- **합계 = 100 유지 (정규화 불필요)** → 조작 안 한 열들은 값 불변

**이점:**
- 누적 오차 원천 제거
- 사용자가 "내가 만진 열만 바뀐다"는 직관과 일치
- `normalizeColWidths`는 호환성 목적(저장된 레거시 값 보정)으로만 사용

### B. 패널에서 조정 (새 UI)

현재 패널(`showTablePanel`) 섹션 목록에 **"열 너비"** 섹션을 "정렬" 섹션 앞에 추가.

```
┌─ 열 너비 (열 N) ─────────────────┐
│  [ 35.0 ] %                      │
│  [ ━━━━━━○━━━━━━━━ ]  (슬라이더)   │
│                                  │
│  [균등 분배]  [자동 맞춤]          │
└──────────────────────────────────┘
```

**구성 요소:**
1. **숫자 입력** — 현재 선택된 열의 `colWidths[col]` 값 (5~80 범위, 소수점 1자리)
2. **슬라이더** — 5~80%, 0.5 단위. 숫자 입력과 양방향 동기화
3. **균등 분배 버튼** — 모든 열을 `100/N`으로 재설정
4. **자동 맞춤 버튼** — `colWidths` 필드 제거 → 렌더러가 `Math.floor(100/numCols)` 적용 (기본 상태)

**변경 규칙:**
- 숫자/슬라이더로 특정 열 N을 조정 시, 드래그와 동일한 이웃 보상 적용
- 균등 분배: `colWidths = Array.from({length:numCols}, () => 100/numCols)`
- 자동 맞춤: `delete b.colWidths`

**왜 패널이 필요한가 (사용자 관점):**
- 비율을 정확하게 맞추고 싶을 때 (예: 50/30/20 보고서 표)
- 드래그가 어려운 상황 (터치패드 정밀도 부족, 접근성 필요 사용자)
- "다 망가진 것 같아서 처음으로 돌리고 싶다" → 자동 맞춤 버튼 한 번

### C. 자동저장 게이팅

**현재 (`blocks.js:208~221`):**
```js
if(b.type==='table'){
  var rows=[], ..., cws=[], ...;
  for(var ri=0;ri<trs.length;ri++){
    ...
    if(ri===0&&tds[ci].offsetWidth&&tblW)cws[ci]=Math.round(tds[ci].offsetWidth/tblW*100)
  }
  b.rows=rows; if(cws.length) b.colWidths=cws
}
```
→ 매 자동저장마다 DOM 측정값으로 덮어씀 (반올림 진동 원인)

**개선:**
- `b.colWidths`가 **이미 존재**하면 DOM에서 다시 읽지 않음 (신뢰)
- `b.colWidths`가 **없으면**(최초 저장 등) 현재 로직 유지
- 드래그/패널 조작은 이미 `colWidths`를 직접 갱신하므로 이 게이팅이 맞음

### D. CSS 제약 강화

`.block-table th, .block-table td { max-width: 800px; }` 추가 → 한 열이 창보다 커져서 전체 레이아웃이 깨지는 경우 방지. `overflow-x:auto`(기존)와 조합되어 스크롤로 대응.

### E. 접근성 — 키보드 리사이즈 (선택)

헤더 셀에 포커스 있을 때 `Alt+←` / `Alt+→`로 해당 열 너비 ±1% 조정. 패널 숫자 입력 보완용. **우선순위: Minor** — Phase 8 이후로 미뤄도 무방.

## 기존 기능과의 충돌 분석

### 충돌 없음 (격리 확인됨)
| 기능 | 이유 |
|------|------|
| **테이블 정렬** (`sortTable`) | `rows` 순서만 변경, `colWidths`는 열 순서이므로 무관 |
| **행 추가/삭제** | `insertRowAt`/`deleteRow`는 `colWidths` 미건드림 |
| **셀 색상** | `cellStyles`/`rowColors`/`colColors`는 별도 필드 |
| **IME 한글 조합** | 리사이즈는 셀 텍스트 입력과 무관 (mouse 이벤트) |
| **컬럼 블록** (`columns` type) | `setupColResize` 별도 함수, px 기반, 완전 격리 |
| **내보내기 (PDF/HTML)** | `<colgroup><col style="width:%">`가 innerHTML에 포함되어 그대로 이식 |
| **검색** (`search.js`) | 표 텍스트 검색만 수행, 너비 무관 |

### 충돌 가능성 있음 (완화책 필요)
| 기능 | 충돌 지점 | 완화책 |
|------|-----------|--------|
| **Phase 8-1 Undo/Redo** | 드래그 리사이즈는 `mousedown` 시 `pushUndoImmediate` 1회 호출. 패널 숫자 입력은 매 입력마다 undo를 쌓으면 히스토리 오염 | 패널 입력은 `debounce 500ms` 후 1회만 undo push |
| **Phase 8-2 블록 D&D** | `.col-resizer`의 `mousedown` 이벤트가 `block-handle`까지 버블링되면 드래그 의도 혼동 | `e.stopPropagation()` 기존 유지 확인 (table.js:390) |
| **열 삽입** (`insertColAt`) | 평균값 계산이 `splice` 이후 길이 기반 | `Math.floor(100/(기존길이+1))` 로 수정 (plan Task에 포함) |
| **자동저장 게이팅** | 페이지 로드 직후 `b.colWidths`는 있지만 DOM은 아직 렌더 전일 수 있음 | 렌더 이후에만 collectPage 호출되므로 안전, 하지만 테스트 필요 |
| **fmtBar 표시** (`listeners.js:1117`) | `th/td` 하드코딩. 리사이저 hover 시 fmtBar가 안 닫힐 가능성 | `.col-resizer` 위에서는 fmtBar 유지, 별도 테스트 |

### 리그레션 위험 (반드시 테스트)
1. **기존 저장된 문서 로드** — 정수 `colWidths:[33,33,34]`가 새 코드에서도 그대로 렌더링되는가
2. **창 크기 변경** — `%` 기반이므로 반응형 동작 유지
3. **표 복사/붙여넣기** — 아직 미구현이지만 Phase 8 이후 검토 시 `colWidths` 필드 포함 여부 확인
4. **빈 `colWidths` + 렌더** — 기본 분배 (`Math.floor(100/numCols)`) 정상 동작
5. **열 1개 표** — 리사이저 무의미, 패널 입력 비활성화 필요

## UX 결정

### 표에서 조정 (드래그) — 유지 + 개선
- 빠르고 직관적 → 대부분 사용자가 이 경로 사용
- 개선: 누적 오차 제거로 예측 가능성 ↑

### 패널에서 조정 — 신규 추가
- 정확한 수치 지정, 접근성, 전체 초기화
- 드래그와 **병존**. 사용자는 선호하는 방식 선택

### "자동 맞춤"의 의미 명확화
- `colWidths` 필드 자체 삭제 → 렌더러가 "균등" 상태로 간주
- 새 열 추가 시에도 재계산 없이 자동 균등 분배 유지
- 사용자에게 **"이 표의 열 너비를 시스템이 알아서 맞춤"** 상태로 복귀

## 비 목표 (이번 계획 범위 아님)
- 행 높이 조정 (세로 리사이즈) — 별도 계획
- 셀 병합 — Phase 8.5 이후
- 다중 열 동시 선택 리사이즈 — 다중 셀 선택 기능 선행 필요
- 표 전체 최대 너비 설정 — 컨테이너 CSS로 이미 해결됨

## 성공 지표
1. **기능**: 드래그 10회 반복 후 조작 안 한 열의 `colWidths` 값 변화 0%
2. **정확성**: 패널에서 "35%" 입력 → 저장 → 새로고침 후 다시 읽어도 35%
3. **호환성**: 기존 Phase 1~7 기간 저장 문서 로드 시 에러 0건
4. **테스트**: 열 너비 관련 유닛 테스트 8개 이상 추가, 전체 85 → 93+ 통과
5. **성능**: 드래그 중 프레임 드랍 없음 (60fps 유지)
